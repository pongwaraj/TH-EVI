# การประเมินจำนวนครั้งชาร์จรายสถานีด้วยข้อมูลอ้างอิง

เพิ่มเมื่อ 19 ตุลาคม 2569 สำหรับเชียงใหม่ ใช้แกน `th_evi/site_demand.py` ร่วมทุกจังหวัด จังหวัดที่ยังไม่มีสถานีอ้างอิงจะไม่ยืมข้อมูลเชียงใหม่

## ขอบเขตผลประเมิน

มีตัวเลขสำหรับวางแผนจากข้อมูลสถานีอ้างอิงและสมมติฐานที่ระบุครบ แต่ยังไม่ผ่านการตรวจความแม่นยำกับสถานีใหม่ `estimate_available=true`, `forecast_available=false` และ `unique_vehicles_per_day=null` ผลเป็นครั้งชาร์จเทียบเท่า ไม่ใช่รถไม่ซ้ำ

สี Heat Map ยังคงเป็นคะแนนคัดกรอง ส่วนจุดคลิกในหน้า Planning และ Analysis แสดงผลประมาณรถเข้าชาร์จจากแบบจำลองสถานีแยกต่างหาก การรายงานการลงทุนไม่หยิบผลทดลองนี้ไปแทนยอดขายอัตโนมัติ ส่วน `method=legacy` ในเชียงใหม่ยังคงตัวเลขเก่าไว้เทียบ แต่ระบุเป็น diagnostic พร้อม `confidence=not_validated` แยกจากความครบของข้อมูล POI/คู่แข่ง

## จุดคลิกและสมมติฐานสถานี

ค่าตั้งต้นหน้าจอคือ 120 kW จำนวน 1 ตู้ 2 ช่องจอด เปิด 24 ชั่วโมง สามารถปรับได้และปิดการแสดงได้ โดยส่งสมมติฐานครบไปยัง API เดิม ไม่เปลี่ยนคะแนน Heat Map เป็นคัน/วันโดยตรง

- แสดง `estimated_charging_visits_per_day` เป็นจำนวนเต็มคัน/วัน จากพลังงานที่สถานีให้บริการได้หารพลังงานต่อครั้ง คำนวณด้วยค่าทศนิยมก่อนปัดเพื่อแสดงผล
- นับการกลับมาชาร์จซ้ำเป็นอีกครั้ง ไม่อ้างว่าเป็นรถไม่ซ้ำ ค่า `unique_vehicles_per_day` ยังเป็น null
- สมมติฐานวางแผนเริ่มต้น: กำลังรับจริงเฉลี่ย 60 kW ต่อคัน, availability 97%, เวลาเข้าออก 5 นาที, kernel 3 กม., outside option 1, relative access 1 และไม่มี market uplift ค่านี้ยังไม่ได้สอบเทียบกับสถานีใหม่
- เชียงใหม่ใช้ 27 kWh/ครั้งจากข้อมูลอ้างอิงเมื่อไม่ระบุเอง สมมติฐานปรับได้ทั้งหมดโดยไม่แก้ฐานข้อมูล
- เวลาเปิดต่ำกว่า 24 ชั่วโมง ตั้งต้นสัดส่วนความต้องการตามชั่วโมงเปิด/24 และให้ปรับได้ ไม่ถือว่าเป็นพฤติกรรมรายชั่วโมงที่วัดจริง
- น้ำหนักเชิงพื้นที่ใช้ shared POI hierarchy v2 โดยไม่ใช้ legacy model_sessions หรือ AADT fallback เป็นจำนวนผู้ชาร์จ
- จังหวัด/ปีที่ไม่มีข้อมูลอ้างอิงหรือจุดนอก support แสดงว่ายังประเมินไม่ได้ ไม่แสดงศูนย์แทนข้อมูลขาด
- ผลยังเป็น conditional estimate ไม่ใช่ validated forecast และยังไม่ใช่แบบจำลองคิวหรือโอกาสรอช่องจอด

## ฐานข้อมูลจริงและการวัดความคลาดเคลื่อน

Meta Mall มีข้อมูล ก.ค.–ก.ย. 2569 รวม 92 วันปฏิทิน โดย meaningful orders คือรายการ Normal ที่มีระยะเวลาอย่างน้อย 5 นาทีและพลังงานอย่างน้อย 1 kWh

- meaningful orders 3,147 รายการ หรือ 34.21 รายการ/วัน
- พลังงาน connector 86,285.97 kWh หรือ 937.89 kWh/วัน
- พลังงานเฉลี่ย 27.42 kWh/รายการ
- ยังไม่มีหลักฐาน uptime และความครบของการนำเข้าทุกวัน จึงไม่คูณชดเชย downtime

การทดสอบเดิมที่คลาดเคลื่อน 6.8% วัดพลังงานต่อรายการโดยทราบจำนวนรายการจริงในเดือนทดสอบแล้ว จึงไม่ได้ยืนยันการพยากรณ์จำนวนผู้ชาร์จ

เพิ่ม baseline ใหม่: ใช้ค่าเฉลี่ยต่อวันของ ก.ค.–ส.ค. (62 วัน) พยากรณ์ ก.ย. (30 วัน) โดยไม่ใช้จำนวนรายการใน ก.ย. เป็นตัวตั้ง

| เป้าหมาย | คาดจากช่วงฝึก | เกิดจริงเดือนทดสอบ | ความคลาดเคลื่อนสัมบูรณ์ของยอดเดือน |
|---|---:|---:|---:|
| พลังงานต่อวัน | 879.89 kWh | 1,057.76 kWh | 16.82% |
| meaningful orders ต่อวัน | 31.31 | 40.20 | 22.12% |

นี่เป็น temporal baseline ของสถานีเดียวเดือนเดียว ไม่ใช่ข้อพิสูจน์ความแม่นยำของสถานีใหม่ และไม่มี daily MAE เพราะมีเพียงยอดรวมช่วงเวลา

## วิธีคำนวณ

1. ใช้พื้นที่ support คงที่ 1 กม. และ exclusion mask เดียวกับ Heat Map
2. ใช้ POI/zone/business area เป็นน้ำหนักสัมพัทธ์ โดยไม่ใช้ `model_sessions` หรือ AADT fallback ของโมเดลเก่าเป็นจำนวนลูกค้า
3. แบ่งน้ำหนักการเลือกไปยังสถานีเดิมและ outside option ด้วยข้อมูล DC/type/power/heads ที่มี ใช้ distance decay เดียวกับ `competition.py` และเปิดให้ระบุรัศมีชัดเจน
4. ปรับขนาด choice pool ให้ยอดสถานีอ้างอิงก่อนเพิ่มสถานีใหม่เท่าพลังงานที่สังเกตได้ นี่คือการอนุมานจากสถานีเดียว ไม่ใช่งบพลังงานจังหวัดที่วัดได้
5. เพิ่มสถานีเสนอใหม่เข้า denominator เดียวกัน แล้วแบ่งพลังงานระหว่างสถานีเดิม สถานีใหม่ และ outside option ใหม่
6. แบ่งช่วงเปิด/ปิดด้วย `demand_in_open_hours_share` และ availability ช่วงปิดใช้ทางเลือกเดิม ช่วงเปิดใช้ทางเลือกที่รวมสถานีใหม่
7. จำกัดพลังงานที่ขายได้ด้วยกำลังรวม กำลังรับจริงเฉลี่ยต่อหัว จำนวนหัว ชั่วโมงเปิด และเวลาเสียบ/ย้ายรถ ส่วนเกินคงเป็น capacity-unserved โดยไม่แอบโยนให้ผู้ให้บริการรายใด
8. แปลงพลังงานที่รับได้เป็นครั้งชาร์จเทียบเท่าตาม `average_session_kwh` ที่ระบุ หากไม่ระบุ เชียงใหม่ใช้ค่าอ้างอิง 27 kWh/ครั้งจาก Meta Mall และแกรนด์ศิริ พร้อมที่มาใน `session_energy_basis` ดู [รายละเอียด](chiang_mai_dc_session_energy.md)

```text
reference share = sum(weight_i * reference utility_i / (outside + sum existing utilities_i))
inferred pool = observed reference connector kWh/day / reference share
new-site share while open = new utility / (outside + sum existing utilities + new utility)
pool = existing after entry + outside after entry + proposed served + capacity-unserved
```

การเพิ่มตู้เปลี่ยนส่วนแบ่งและขีดจำกัดการให้บริการ โดยไม่ทำให้ choice pool เพิ่มเอง การแบ่ง display grid ไม่ใช่ input ของวิธีนี้ จึงไม่เพิ่มจำนวนครั้งชาร์จเมื่อปรับ grid

## ช่องทางเรียกใช้

- `GET /api/charging-demand/site-reference?province=Chiang%20Mai` แสดงข้อมูลอ้างอิงและผลทดสอบ demand baseline
- `GET /api/charging-demand/basis` เพิ่มสถานะ `site_demand_preview`
- `POST /api/charging-demand/site-preview` ต้องระบุพิกัด ปี สเปก เวลาเปิด availability สมมติฐานการเลือก และรายการ scenarios ครบ พลังงาน/ครั้งใช้ค่าอ้างอิงจังหวัดได้เมื่อมีหลักฐาน หรือระบุเองเพื่อ override
- รับเฉพาะปีเดียวกับข้อมูลสังเกต ไม่ extrapolate 10 ปีด้วยอัตราเติบโตที่ตั้งเอง
- รายการคู่แข่งที่ขาด type/power/heads แสดงใน `missing_competitor_evidence` ไม่แทนค่ากำลังหรือจำนวนหัวที่แต่งขึ้น

ตัวอย่างรัน Tanawan Park:

```powershell
python -m scripts.preview_site_demand --request Analysis/Tanawan_Park/reference_transfer_request.json --output outputs/tanawan_park_area_analysis/site_demand_reference_transfer.json
```

ไฟล์ตัวอย่างกำหนดกรณี DC 120 kW 1 ตู้ 2 หัว เปิด 18 ชั่วโมง availability 95% พลังงานต่อครั้งอ้างอิง meaningful orders 27.42 kWh และกำลังรับจริงเฉลี่ย 60 kW/หัว เป็นสเปกและเงื่อนไขเพื่อทดสอบ ยังไม่ใช่ข้อเท็จจริงหน้างาน

`demand_in_open_hours_share=0.987138...` มาจากสัดส่วน **Normal orders** ที่ Meta Mall เริ่มช่วง 06.00–24.00 น. (3,377 จาก 3,421 รายการ) การถ่ายโอนรูปแบบเวลาไป Tanawan Park เป็นสมมติฐาน ไม่ใช่ข้อมูลผู้ใช้ Tanawan Park

ตัวอย่างทดสอบ relative access 0.5 / 1.0 / 1.5 และ market multiplier 1 เท่ากันทั้งหมด เพื่อให้เห็นความไวต่อทางเข้า/ความสะดวก ช่วงนี้ไม่ใช่ Low/Base/High ที่ fit จากข้อมูล ไม่ใช่ prediction interval และเงื่อนไข `public_access_assumed=true` ไม่ได้ยืนยันว่าสวนอนุญาตให้บุคคลภายนอกเข้าใช้งานจริง

ผล local กับ inventory ที่มี ณ วันที่วิเคราะห์:

| กรณีทดสอบการเข้าถึง | connector kWh/วัน | ครั้งเทียบเท่าต่อวัน ที่ 27.42 kWh/ครั้ง | ที่ 35 kWh/ครั้ง |
|---|---:|---:|---:|
| relative access 0.5 | 183.52 | 6.69 | 5.24 |
| relative access 1.0 | 333.44 | 12.16 | 9.53 |
| relative access 1.5 | 460.04 | 16.78 | 13.14 |

พบคู่แข่ง 33 รายการที่ยังขาดบางส่วนของ type/power/heads ในบริเวณที่อาจกระทบการถ่ายโอนจาก reference หรือ candidate จึงต้องอ่านตัวเลขข้างต้นพร้อม `missing_competitor_evidence` ไม่ควรนำช่วง access sensitivity ไปอ้างว่าครอบคลุมความไม่แน่นอนของคู่แข่งแล้ว

ผลตรวจรอบนี้: 90 tests ผ่าน ครอบคลุมบัญชีรวมก่อน/หลังเพิ่มสถานี การจำกัดกำลัง ช่วงเปิด/availability ชนิดข้อมูลไม่ถูกต้อง การไม่ยืม reference ข้ามจังหวัด การแยกค่าพลังงานต่อครั้งกับยอดต่อวัน และการป้องกันการใช้ screening/conditional estimate เป็น financial projection การผ่าน tests พิสูจน์พฤติกรรมโค้ด ไม่ใช่ความแม่นยำของทำเล

## ก่อนใช้เป็น forecast สำหรับลงทุน

ต้องยืนยันการเข้าใช้สาธารณะ/พิกัดทางเข้า สเปก/สถานะคู่แข่งจริง และนำเข้ารายการชาร์จต่อวันพร้อม uptime ของหลายสถานี เพื่อ fit และ hold out ทั้งเวลาและสถานที่ รวมทั้งตรวจ home/work access, OD และ station choice รายสถานี การมีค่าเฉลี่ยพลังงานต่อครั้งที่ดีเพียงอย่างเดียวไม่ปิดช่องว่างนี้
